# 배포 방식 개요

이 문서는 `dev` 브랜치의 수집 데이터와 CSV/ECR 뷰어를 배포하는 두 방식의 관계를 정리한다.
현재 채택된 방식은 Cloudflare R2이며, 실제 운영 절차는 [배포계획-R2.md](배포계획-R2.md)를
기준으로 한다. 이 문서의 Git-정적 방식은 R2를 사용할 수 없을 때의 롤백 대안이다.

## 1. 현행 구성

| 구성 | 역할 | 상태 |
|---|---|---|
| `public/` | 사전공고·본공고 CSV와 ECR 결과 조회 UI | 구현 완료 |
| `src/worker.js` | 공유 비밀번호 게이트 → 정적 자산 또는 `/data/**` R2 중계 | 구현 완료 |
| `wrangler.jsonc` | `public/` Assets·`DATA` R2 바인딩·Worker 우선 실행 선언 | 구현 완료 |
| `collector/collector.js` | 공공데이터 API 수집과 일별 gzip 생성 | 구현 완료 |
| `collector/compact.js` | 재수집 창 밖의 완료 월을 월별 gzip으로 봉인 | 구현 완료 |
| `uploader/upload.js` | ETag 비교 기반 증분 업로드·안전한 삭제·상태 왕복 | 구현 완료 |
| `.github/workflows/collect.yml` | 매일 KST 05:00 수집·업로드 | 구현 완료 |

R2 바인딩은 `wrangler.jsonc`가 선언하므로 저장소에서 확인된다. 저장소에서 확인할 수 없는
Worker 배포 여부, `GATE_PASSWORD` 시크릿, GitHub Secrets의 실제 등록 여부는 별도로 확인해야 한다.

## 2. 배포 데이터

브라우저가 `/data` 아래에서 읽는 키는 다음뿐이다.

| 키 | 생성 주체 |
|---|---|
| `index.json` | collector·uploader |
| `{pre,bid}/YYYY/MM/DD.csv.gz` | collector |
| `{pre,bid}/YYYY/MM.csv.gz` | compact |
| `analysis-index.json` | analyzer |
| `analysis/bid/<공고번호>.json` | analyzer |

`data/raw/`, `data/backup/`, `data/files/`, `data/norm/`, `data/text/`, 상태·오류 파일은 웹 배포
대상이 아니다. Worker의 R2 중계도 이 경로를 허용하지 않는다.

인덱스 항목은 다음 구간 스키마를 사용한다.

```json
{
  "mode": "bid",
  "begin": "2026-08-01",
  "end": "2026-08-01",
  "path": "bid/2026/08/01.csv.gz",
  "count": 123
}
```

월별 봉인 항목은 `begin`이 월 1일, `end`가 월 말일이다. 프런트는 항목 구간과 조회 구간이
겹치는 파일을 읽은 뒤 행 단위로 날짜를 다시 검사한다.

## 3. 채택한 R2 방식

```text
GitHub Actions (매일 KST 05:00)
  → dev 체크아웃
  → R2에서 sync-state.json 복원
  → 최근 35일 수집
  → 변경된 gzip·인덱스·분석 결과만 R2 업로드

Cloudflare Worker (src/worker.js)
  → 게이트 인증
  → /data/** 는 비공개 R2 버킷 DATA 중계
  → 그 외는 public/ 정적 자산(ASSETS)
```

R2 방식에서는 `data/`를 Git에 넣지 않으며 빌드 명령도 필요 없다. 정적 자산 디렉터리는
`wrangler.jsonc`가 `public`으로 선언한다. 상세 설정, 운영 명령, 검증 및 롤백 절차는 R2 문서를
따른다.

## 4. Git-정적 대안

R2를 사용하지 않을 경우 gzip과 분석 JSON을 Git에 포함하고 정적 자산으로 복사할 수 있다.
다만 현재 저장소에는 이 방식에 필요한 `build.sh`가 없으며 `/data/**`는 Worker가 담당한다.

전환 절차는 다음과 같다.

1. `.gitignore`의 `/data/` 전체 제외를 배포 제외 대상만 남기는 규칙으로 좁힌다.
2. `data/`에서 2장의 배포 대상만 `public/data/`로 복사하는 빌드 스크립트를 추가한다.
3. `src/worker.js`의 `/data/**` 분기를 제거해 정적 자산이 그 경로를 받게 한다.
4. `wrangler.jsonc`의 `assets.directory`를 새 빌드 출력에 맞춘다.
5. 크론의 `uploader/upload.js` 단계를 데이터 커밋·푸시 단계로 교체한다.
6. 배포 후 gzip에 `Content-Encoding`이 붙지 않는지 확인한다. 브라우저가
   `DecompressionStream("gzip")`으로 직접 압축을 해제하기 때문이다.

다음 항목은 Git에 포함하면 안 된다.

```gitignore
data/sync-state.json
data/sync-errors.json
data/backfill-errors.json
data/analysis-state.json
data/download-errors.json
data/raw/
data/backup/
data/files/
data/norm/
data/text/
```

## 5. 공통 보안 원칙

- `.env`와 API 자격증명은 커밋하지 않는다.
- `GATE_PASSWORD`를 설정하지 않으면 게이트는 통과 모드로 동작한다. 공개 배포 전에 반드시
  `npx wrangler secret put GATE_PASSWORD`로 값을 등록한다. `wrangler.jsonc`에는 넣지 않는다.
- `assets.run_worker_first`를 `true`로 유지한다. 끄면 `/`와 `/app.js`가 게이트 앞에서 서빙된다.
- R2 버킷의 Public URL은 활성화하지 않는다.
- R2 토큰은 대상 버킷에 한정된 Object Read & Write 권한만 부여한다.
- `/data/**` 중계는 화이트리스트 밖의 `raw/`, `state/` 등을 404로 거부해야 한다.
- 게이트 뒤 응답은 공유 캐시에 남지 않도록 `Cache-Control: private`을 유지한다.

## 6. 선택 기준

현행 데이터는 바이너리 gzip 파일이 많고 재수집으로 같은 경로가 갱신된다. Git 방식은 초기
커밋뿐 아니라 변경된 gzip 전체가 히스토리에 계속 누적된다. 따라서 저장소 크기와 정적 자산 파일 수를
관리해야 하는 Git-정적 방식보다 데이터 수명주기를 저장소와 분리하는 R2가 현재 구조에 적합하다.

R2에서 문제가 될 수 있는 지점은 파일 하나당 Worker 요청이 하나 발생한다는 점이다.
현재 구현은 이를 다음 방식으로 줄인다.

- 완료 월을 월 파일 하나로 봉인한다.
- 과거 파일은 1년 `immutable`, 최근 일별 파일은 5분 캐시한다.
- 파일 URL에 전역 버전 쿼리를 붙이지 않아 과거 캐시를 유지한다.
- `index.json`만 매번 최신 목록을 확인한다.

플랜별 한도와 가격은 바뀔 수 있으므로 실제 배포 시 Cloudflare 대시보드의 현재 값을 기준으로
판단한다.
