# 출시 검증 및 장애 대응

현재 상태: **로컬 검증 완료 항목은 있으나 상용 출시 완료는 아님**. 운영 배포, 원격 AI·R2 통합 검증, 실제 모델의 필드별 정확도와 무료 플랜 처리 한도는 미확인이다. 이 문서의 원격 작업은 운영자 승인 후에만 실행한다.

2026-10-05 기준 선별 관문: 확정 라벨 4개 문서 43개 번호가 모두 일치하고 오검출 0건이다(양산선 29,
4대보험 4, 한국투자공사 4, 수협 6). SR-MaaS는 추정 라벨 20개로 참고 결과다. 2026-09-26에 기록된
누락·추가 선별([8부](history/2026-09-pdf-local-review.md))은 **선별기 결함이 아니라 추출기 차이였다** —
그때는 pypdf로 뽑았고, 선별이 좌우로 붙은 표의 열 위치를 보므로 `pdftotext -layout` 외의 추출기로는
라벨이 재현되지 않는다. 추출 기준은 [ECR](ecr.md)에 적었다. 다만 이 표본 결과를 PDF 처리 전체나
필드별 추출 정확도로 일반화하지 않는다.

테스트 개수 자체는 완료 기준이 아니다. 각 검증 범위와 한계는 [service-quality.md](service-quality.md)에 기록한다.

### 최근 로컬 통합 재검증

사용자가 운영 배포 없이 로컬 검증을 선택한 범위를 유지했다. 현재 작업 트리에서 전체 397개 테스트와 브라우저 두 화면 크기 검증을 재실행해 통과했다. 실제 브라우저 인증을 포함한 로컬 workerd/R2 테스트는 외부 요청 0건으로 통과했다. `npm audit --audit-level=high`는 알려진 취약점 0건을 보고했고, Wrangler dry-run은 92.70 KiB 번들 및 AI/DATA/ASSETS 바인딩을 확인하고 배포 없이 종료했다. 확정 라벨 2개 문서의 대상 번호 33개는 누락·오검출 없이 선별됐다. 별도 추정 라벨 20개는 확정 품질 지표에 합산하지 않는다. 이는 모델 호출이나 규격 필드 정답 검증이 아니다. `npm ci`는 이전 통합 검증에서 성공했으며 이번 회차에는 재실행하지 않았다.

합성 검색 1만·10만·25만 행은 각각 5천·5만·12만5천 개의 기대 결과와 고유 ID 수가 일치했고 조회 실패는 0건이었다. 이번 로컬 관측 시간은 91/365/910ms였으며 테스트를 병렬 실행한 환경의 참고값이다. 운영 SLO·최대 메모리·실제 모바일 성능을 보장하지 않는다. 브라우저 검사는 100개 장비 카드와 구형 항목 1개를 함께 표시하고 미분류 항목·키보드 원문 접근·모달 가로 넘침을 확인했다.

로컬 통과로 대체할 수 없는 항목은 위 표의 오른쪽 열에 남긴다. 저장 결과의 구조·표시 필드 타입 검증은 구현됐지만 의미적 정확성을 보장하지 않는다. 추가 검증 우선순위는 실제 모델의 필드별 정답 대조, 실데이터 검색의 최대 메모리·지연, 실제 모바일·스크린리더 사용성이다. 현재 20만 건 한도는 저장 검색의 표시 배열에만 적용되므로 전체 메모리 상한이나 최신순 상위 결과 보장으로 홍보하지 않는다. 실제 모델/운영 데이터 검증과 원격 CI·배포 설정은 별도 승인 전 수행하지 않는다.

## 2. 배포 전 로컬 관문

### 실제 규격 정확도 검증에 필요한 입력

현 로컬 평가 자료를 재확인한 결과, `gong-go-eval`에는 원문 텍스트 3개와 이전 작업 명세 텍스트가 있다. `eval-selection.mjs`의 확정 정답은 요구사항 번호의 장비/비장비 분류이며 CPU·수량·용량 등 필드별 정답이 아니다. 이 자료만으로 실제 모델의 필드 정확도나 규격 누락률을 계산하지 않는다.

추가 AI 호출 없이 다음 검증을 진행하려면 운영자가 이미 보유한 다음 자료가 필요하다. 기밀 자료는 공개 저장소나 CI 산출물에 넣지 않는다.

1. 같은 문서 버전의 제안요청서 또는 비식별 원문 텍스트와, 실제 분석에서 내려받은 ECR JSON/CSV. 합성 스텁 응답은 실제 모델 결과를 대체하지 않는다.
2. 검토자가 확인한 필드별 정답: 요구사항 ID, 장비명·종류, 항목, 값, 단위, 수량 적용 대상(장비당/전체), 조건(이상/이하·신규/증설·Raw/Usable), 원문 페이지 또는 근거 문장. 정답이 없으면 우선 정답 검토가 필요하며 추정 라벨을 확정으로 취급하지 않는다.
3. 결과에 빠진 요구사항·필드와 잘못 추가된 필드를 함께 표시한 검토 기록. 출력에 있는 값만 맞춰 보는 검사는 누락 검증이 아니다. 동일 규격의 중복과 서로 다른 장비의 동일 값도 구분한다.

자료가 제공되면 문서별·항목별로 정답/누락/잘못된 추가/조건 또는 소속 오류를 분리해 대조한다. 임의의 높은 정확도 목표를 달성한 것으로 선언하거나 번호 선별 33개 일치를 필드 정확도로 환산하지 않는다. 실제 PDF 변환, 무료 뉴런 소모, 운영 HTTPS·R2·원격 CI는 이 오프라인 대조만으로 검증되지 않으며 기존 승인 경계를 유지한다.

각 명령의 종료 코드가 0인지 별도로 확인한다. 셸에서 연속 실행한 마지막 명령의 성공으로 앞 단계 실패를 가리지 않는다.

```text
npm ci
npm test
npm run test:runtime
npm run test:runtime-browser
npm audit --audit-level=high
npm run test:browser
npm run test:search-load
npm run test:selection
npx wrangler deploy --dry-run
git diff --check
```

- 브라우저 명령은 기본적으로 설치된 Edge를 사용한다. CI는 테스트용 Chromium을 설치한다.
- `test:selection`은 저장소 옆 `gong-go-eval` 원본을 필요로 한다. 원본이 없으면 성공으로 간주하지 않는다. 디렉터리는 명령 인자로 지정할 수 있다.
- 변경 파일·새 파일과 lockfile이 모두 출시 묶음에 포함되는지 확인한다. 원문 문서, 암호, 로컬 캡처는 커밋하지 않는다.
- 운영 Worker 이름과 바인딩을 확인한다. 현재 설정은 `gong-go`, `AI`, `DATA`, `ASSETS`다. `wrangler dev`의 AI 바인딩도 remote=true이므로 무심코 호출하면 실제 사용량이 발생할 수 있다.

## 3. 승인 후 운영 확인

1. 현재 배포 버전 ID와 코드 커밋, 시크릿 이름, 계정 플랜, Workers AI 사용량을 기록한다. 시크릿 값은 로그·이슈·스크린샷에 남기지 않는다.
2. 기본 사이트용 `GATE_PASSWORD`, 갱신용 `GITHUB_PAT_TOKEN`, 중계용 `DATA_GO_KR_PROXY_TOKEN`, 최신 조회용 `DATA_GO_KR_SERVICE_KEY`, AI 사용용 `AI_ANALYSIS_PASSWORD` 설정을 확인한다. AI 전용 암호는 16~512자다. Workers AI 바인딩 호출용 토큰을 브라우저에 넣지 않는다.
3. 승인된 코드만 main에 푸시한다. main 푸시는 Workers Builds가 곧바로 운영에 배포한다. AI 인증 v2 때문에 기존 AI 쿠키가 무효화되고 재입력이 필요하다. ECR cloud-v4는 이전 작업 캐시를 새 작업으로 자동 승계하지 않으므로 재분석 비용이 생길 수 있다.
4. 로그아웃 상태의 `/api/ecr`, `/api/ai-access`, `/api/ask` 차단을 확인한다. 사이트 로그인만 한 상태에서 AI 잠금을 풀지 않고 ECR 실행을 시도해 추론·변환이 시작되지 않는지 확인한다.
5. 허용한 사용량 범위 안에서 작은 문서 하나로 잠금 해제→변환→분석→저장→조회→동일 파일 재개를 확인한다. 기록할 항목은 파일 식별자, 대상 번호, 완료 구간 수, 단계별 시간, 사용량 변화, 오류 참조 번호다. 기밀 RFP를 검증 목적으로 임의 업로드하지 않는다.
6. 실제 PDF 변환과 대형 결과 병합의 Worker CPU·메모리·지연을 확인한다. 작은 TXT 성공으로 PDF나 대형 문서 성공을 주장하지 않는다.
7. 수량·CPU·메모리·Raw/Usable·이중화·라이선스·유지보수 조건을 원문과 사람이 대조한다. 번호 일치나 원문 문자열 일치만으로 전체 결과를 verified로 승격하지 않는다.

계정 무료 한도는 이 앱의 8,000뉴런 예약 장부와 같지 않다. 문서 변환과 다른 앱 사용량을 포함한 계정 상태를 확인한다. 사용량이 불확실하면 자동 반복 실행을 중단하고 조사한다.

## 4. 장애 대응

- 권한 문제: 사이트 로그인과 AI 전용 잠금을 구분한다. 쿠키를 로그로 제출받지 않는다. 암호 설정 오류는 허용 길이와 이름만 확인한다.
- 예산 문제: budget 단계의 앱 예약 한도와 공급자 quota 오류를 구분한다. 장부를 지워 제한을 우회하지 않는다. UTC 날짜가 바뀌는 한국시간 오전 9시 기준을 확인한다.
- 출력 잘림: 완료되지 않은 구간이 저장 완료처럼 보이지 않는지 확인한다. 허용 출력 확대·분할 후에도 실패하면 문서를 나누고 기존 완료 구간은 유지한다.
- 저장·병합 실패: 원문, 작업, 완료 구간을 삭제하지 않는다. 같은 파일 재개로 복구되는지 확인한다. 추론 성공 뒤 저장 자체가 실패하면 재추론 비용이 생길 수 있다.
- 통신 시간 초과: 브라우저의 대기 종료가 서버 실행 취소라는 뜻은 아니다. 즉시 반복 요청하지 않고 저장 결과와 참조 번호를 확인한다.
- 이상 사용: 추가 실행을 중단하고 운영자가 AI 시크릿의 회전 또는 비활성화를 결정한다. 이미 진행 중인 요청을 소급 취소하거나 환불한다고 약속하지 않는다.

로그에는 `ecr_failure`의 stage/reference/code/status를 사용한다. 원문·비밀번호·서명 쿠키·공급자 전체 응답은 붙이지 않는다. 정산·잠금 해제 경고도 함께 확인한다.

## 5. 되돌리기

운영자가 대상 Worker와 이전 버전 ID를 확인하고 승인한 뒤 `npx wrangler rollback <이전-버전-ID>`를 실행한다. 명령 형식은 현재 설치된 Wrangler의 `rollback --help`로 확인할 수 있다. 버전을 생략해 대상을 추측하지 않는다. main 푸시가 자동 배포되므로, 되돌린 뒤 문제 커밋을 `git revert`로 되돌려 푸시하지 않으면 다음 푸시가 문제 코드를 다시 배포한다.

코드 되돌리기가 R2 데이터·시크릿·소모된 뉴런까지 복구하는 것은 아니다. 이전 코드의 보안 수정 전 동작과 쿠키 호환성도 다시 검토한다. 자동 R2 삭제나 예산 장부 초기화를 복구 절차에 포함하지 않는다. 복구 후 사이트 게이트, AI 잠금, 저장 결과 조회부터 확인하고 실제 추론은 사용량 승인 범위 안에서만 재검증한다.
