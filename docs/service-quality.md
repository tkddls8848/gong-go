# 현재 서비스 품질 개선 기준

범위: 사용자 선택에 따라 회원·결제·조직 기능 확장보다 공고 검색과 ECR 분석의 정확성, 속도, 보안, 사용성을 우선한다. 시장 순위를 완료 기준으로 주장하지 않는다.

## 2026-09-25: 비용·동시 실행·내보내기 보강

- ECR 잠금 취득 후 완료 결과와 세분화 진행 상태를 다시 읽는다. 이전 요청이 이미 끝났으면 AI를 다시 호출하지 않는다.
- 완료 구간 저장 후 잠금을 해제한다. 해제는 취득한 ETag에 대한 조건부 쓰기이며, 만료된 이전 요청이 새 요청의 잠금을 삭제하지 않는다.
- 잠금 해제 실패는 저장된 성공 결과를 버리지 않는다. 다음 요청은 완료 캐시를 읽을 수 있고, 미완료 구간의 잠금은 3분 후 다시 취득할 수 있다.
- 추론이 잠금 유효 시간을 넘기면 그 응답을 구간 완료로 저장하지 않는다. 서버가 반환하는 대기 시간에 따라 화면이 재시도한다.
- AI 사용량 정산은 예약한 UTC 날짜에 적용한다. 정산 저장 오류는 성공한 추론 응답을 버리지 않으며 예약액을 유지한다. null·문자열 등 불확실한 사용량은 환급 근거로 사용하지 않는다.
- 공고·ECR CSV 다운로드는 수식 시작 문자를 텍스트 처리한다. CR/LF, 쉼표, 따옴표를 셀 안에 보존한다. 서버의 원본 문자열은 변경하지 않는다.
- 작업 크기 상한은 유지한다. R2 내부 요청을 외부 요청 50회 한도와 혼동하던 주석은 정정했다. 근거: [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) 및 [R2 조건부 쓰기](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).

## 검증 방법

### ECR 결과 미저장

ECR 분석 결과는 서버·R2에 저장하지 않고 화면 응답으로만 전달한다. 분석 인덱스(`analysis-index.json`)와 저장 결과 조회 경로는 제거했으므로 목록 갱신이 이를 검사하거나 실패를 표시하지 않는다.

### 검증 플래그와 오류 정보 충돌

ECR 상세 상태·장비 요약 안내·CSV 검증 열은 공통 표시 판정을 사용한다. 저장된 verified=true가 있어도 명시적 누락, 검증 오류, 미추출 번호, 번호 대조 불가/부분 일치, 항목의 불확실 정보가 있으면 원문 확인 필요로 표시한다. coverage.missingIds에만 있는 미추출 번호도 상세 경고에 표시한다. 충돌 정보 없는 구형 플래그는 유지하며 저장 결과 자체는 수정하지 않는다. 이는 새로운 자동 검증이나 원문 의미 대조가 아니라 모순된 성공 표시 방지다. 목록 배지는 별도 분석 인덱스의 요약 값이며 이 전체 결과 판정의 적용 대상이 아니다.

전체 400개 테스트와 두 화면 크기의 브라우저·CSV 다운로드 검증이 통과했다. 회귀 검사는 충돌 유형별 화면·CSV 판정 일치, 입력 불변성과 구형 표시 호환성을 확인한다. 운영 배포·실제 AI 호출은 하지 않았다.

### CSV 장비별 규격 소속 보존

요구사항 하나에 여러 장비가 포함된 경우 CSV가 규격 배열을 평탄화하면서 장비명과 개별 출처를 잃던 문제를 수정했다. 기존 19개 열과 요구사항당 한 행은 유지하고, 수량·장비 요구사항·근거 셀에서 장비 순번·종류·명칭으로 소속을 연결한다. 근거에는 장비별 출처를 우선 기록한다. 규격 없는 장비도 명칭과 원문 확인 경고를 남기며, 구형 기본규격의 요구사항과 수량 0도 보존한다. 저장 데이터는 변경하지 않는다.

전체 399개 테스트가 통과했으며 다중 장비의 수량·근거·개별 출처 연결, 빈 규격 장비, 구형 기본규격을 회귀 검사한다. 이 표기는 원문 대조를 돕는 것이며 장비 구분 자체의 모델 정확성을 보장하지 않는다.

브라우저 검사도 저장 결과 fixture 조회부터 실제 다운로드 버튼·UTF-8 BOM 파일 생성까지 확장했다. 내려받은 파일은 테스트에서만 별도 수집기 CSV 파서로 읽어 19개 열, 다중 장비 수량과 근거·개별 출처의 정확한 연결, CR/LF·쉼표·따옴표, 빈 규격 장비, 구형 수량 0, 수식 문자열의 텍스트 보호를 확인한다. 1440/390 화면 크기에서 모두 통과했다. 첫 시도는 메뉴 선택 후 자동 닫힘을 테스트가 빠뜨려 실패했으며 메뉴를 다시 여는 정상 동선으로 수정했다. Excel 앱 자체에서의 표시나 실제 원격 모델 결과를 검증한 것은 아니다.

### 구형·신형 저장 항목 혼합 표시

schemaVersion 2 결과 안에 장비요약 필드가 없는 구형 항목이 섞이면 전체 장비 요약을 숨기던 조건을 수정했다. 표시 가능한 신형 규격은 유지하고, 요약 형식이 없는 요구사항의 번호·명칭과 집계 범위를 따로 안내한다. 구형 항목은 기존 상세 원문·기본규격에서 확인하며, 자동 재분석이나 비용 발생은 없다. 모든 항목이 구형이면 장비 0건으로 집계하지 않는다. 입력 자료와 제외된 규격 경고는 보존한다.

### 저장 장비 분류의 조용한 누락 방지

서버·스토리지·스위치 이외의 종류 또는 종류가 없는 저장 장비는 요약에서 숨기지 않고 `분류 확인 필요` 그룹에 표시한다. 원래 종류·규격·근거와 출처를 보존하며, 추정 재분류나 추출 대상 확대는 하지 않는다. 그룹 건수와 카드 건수의 일치, HTML 이스케이프, 입력 데이터 불변성을 회귀 검사한다. 종류별 미추출과 분류 미확정을 구분하기 위한 표시이며 모델 정확도 검증은 아니다.

전체 395개 테스트와 두 화면 크기의 브라우저 회귀가 통과했다. 100개 장비 카드에 미분류 항목을 포함해 카드가 누락되지 않고 분류 경고가 보이는지 확인했다. 첫 브라우저 검사는 건수 배지의 실제 줄바꿈을 공백으로 가정해 실패했으며, 의미와 숫자는 엄격히 비교하면서 레이아웃의 공백·줄바꿈을 허용하도록 검사만 수정했다. 운영 배포·실제 AI 호출은 하지 않았다.

### 저장 ECR의 표시 필드 검증

저장 결과 조회·분석 완료·CSV 내보내기가 공유하는 검증에서 메타데이터, 요구사항 이름·ID·원문, 장비 이름·종류·출처와 기본규격의 표시 필드 타입을 검사한다. 객체나 배열이 암묵적으로 문자열로 변환되어 정상 규격처럼 출력되는 것을 막는다. 구형 숫자 수량과 선택 필드 생략은 유지한다. `원문 확인`인 규격은 항목·값·근거가 모두 비어 있지 않아야 하며, 미검증 규격의 근거 생략은 허용한다. 이는 의미적 정확도나 근거 문장의 실제 소속을 재검증하는 기능은 아니다.

전체 393개 테스트, 실제 브라우저와 로컬 Worker 인증 통합, 데스크톱·모바일 화면 크기 회귀가 통과했다. 운영 배포나 실제 AI 호출은 하지 않았다.

### 실제 브라우저와 로컬 Worker 인증 통합

`npm run test:runtime-browser`는 모형 API 응답 대신 로컬 workerd HTTP 서버에 실제 브라우저로 로그인하고 AI 잠금을 해제한다. AI 쿠키의 `/api` 경로, HttpOnly, SameSite=Strict 속성과 JavaScript 접근 차단을 확인한다. 기존 로그아웃 경로의 리다이렉트를 따라 두 인증 쿠키가 삭제되고, 미리 복사한 AI 쿠키도 로컬 R2 취소 기록으로 거부되는지 검증했다. 테스트가 통과했으며 외부 요청은 0건, 모델은 스텁으로 실제 뉴런을 사용하지 않았다.

이 검사는 HTTP 로컬 환경이므로 운영 HTTPS의 Secure 강제나 실제 도메인의 사이트 간 요청 정책을 검증한 것은 아니다. 품질 CI 정의에는 브라우저 설치 후 실행하도록 추가했지만 원격 CI는 실행하지 않았다.

### ECR 번호 대조 추가

업로드 시 선별된 상세 장비 표의 번호와 미선별 번호를 별도로 저장한다. 최종 결과의 `coverage`는 대상 번호, 유효 규격을 추출한 번호, 미추출 번호, 선별 범위 밖 추출 번호를 구분한다. `누락`은 더 이상 무조건 빈 배열이 아니며 선별 대상 중 미추출 번호를 담는다. 명칭만 있고 유효한 규격이 없는 항목이나 ID 근거가 불확실한 항목은 완료로 세지 않는다.

화면에는 대상/추출/미추출 건수를 표시한다. 모든 번호가 일치해도 `verified`는 false로 유지하며, 이는 필드별 규격 누락 검증을 대신하지 않는다. 상세 표를 식별하지 못한 작업과 번호 목록 없는 구형 작업은 확인 불가로 표시한다. 같은 파일 재업로드 시 기존 구간과 추론 캐시를 보존하면서 번호 목록을 보완한다. 재업로드하지 않은 구형 저장 결과는 자동 갱신하지 않는다.

추가 회귀 테스트는 빈 모델 응답의 누락 저장, 미선별 번호 분리, 중복 번호 정규화, 근거 없는 결과, 구형 작업, 화면의 범위 표시를 검증한다. 전체 262개 테스트 통과 및 Wrangler dry-run 통과. 실제 문서별 재현율·필드 누락률 검증은 다음 관문으로 남아 있다.

`npm test`: 기존 테스트에 동시 요청의 캐시 재확인, 잠금 소유권, 저장 순서, 해제 장애, 만료 응답, UTC 경계 정산, 정산 저장 장애, 잘못된 사용량, CSV 보안을 추가했다. 테스트는 모형 저장소와 모델을 사용하며 실제 뉴런을 사용하지 않는다.

`npx wrangler deploy --dry-run`: 배포 패키지와 바인딩 구성을 확인한다. 운영 배포 또는 원격 AI 품질 검증을 의미하지 않는다.

## 다음 품질 관문과 미검증 영역

### 합성 대용량 검색 측정

동시 큰 파일 2개·0건 매칭 파일·조회 실패 파일 혼합에서 행 누락/중복, scanned/done/failures 증분 합계, 최종 완료 1회를 검증했다. 전체 조회 실패와 큰 파일 전송 도중 새 검색으로 전환하는 회귀도 추가했다. 전체 356개 테스트 통과. 품질 CI 정의에 합성 대용량 검색 명령을 포함했으며 원격 CI 실행이나 push는 하지 않았다. 시간 측정값 자체에 공격적인 합격 기준을 걸지는 않고, 정답·묶음 상한·60초 종료 제한을 검사한다.

후속 개선: Worker 결과 전송을 묶음당 최대 4,000행으로 제한하고 묶음 사이에 이벤트 루프를 양보해 취소 메시지를 처리한다. 행 수/스캔 수/완료 파일 수 집계와 전달 도중 취소를 검증했고 전체 353개 테스트 및 브라우저 두 화면 크기 검증이 통과했다. 첫 취소 테스트는 VM 사이 Promise 처리 순서를 잘못 가정해 실패했으며, 실제 첫 메시지 수신을 기다리도록 수정했다.

같은 합성 부하의 개선 후 관측은 1만/10만/25만 행 각각 115/500/1,280ms, 최대 메인 스레드 간격 18/46/40ms였다. 변경 전 25만 행의 1,572ms/354ms 대비 개선됐지만 단일 PC 실행 간 비교이며 반복 통계나 운영 SLO는 아니다. 벤치마크에 최대 메시지 행 수 4,000 검사도 추가했다. 전체 CSV 파싱과 matched 임시 배열은 여전히 파일 단위로 생성한다.

`npm run test:search-load`는 실제 브라우저 검색 Worker에 로컬 gzip CSV 1만·10만·25만 행을 제공한다. 전체 행 스캔 수, 짝수 ID만 있는 정답 집합(각 5천·5만·12만5천 건), ID 범위·중복·제목 보존·실패 0건을 검증한다. 외부 요청은 차단하고 알 수 없는 경로가 있으면 실패한다. Worker 생성부터 결과 수신/검증까지 60초 제한을 둔다.

현재 개발 PC의 headless Edge 두 번째 실행 관측은 각각 114ms / 729ms / 1,572ms였고, 16ms 간격의 메인 스레드 타이머 최대 간격은 17ms / 137ms / 354ms였다. 첫 실행의 25만 행은 1,588ms / 최대 간격 370ms로 유사했다. 큰 결과 메시지 전송과 메인 스레드 수신/정답 검사 비용이 남아 있어 결과 묶음 처리 개선 후보로 삼는다. 이 간격에는 벤치마크 검증 코드 비용도 포함되므로 앱 UI 정지 시간과 동일시하지 않는다.

단일 Worker·단일 합성 파일 검사이며 앱 정렬/DOM 렌더링, 여러 Worker 경합, 실제 모바일 기기, 최대 힙 메모리나 운영 SLO를 검증한 것은 아니다. 원격 AI·운영 R2는 사용하지 않았다.

### 검색 응답 및 상태 검증 상세

실제 수집기 `serializeCsv`→gzip→화면 `fetchCsvText`/`scanText` 파일 계약 검증을 추가했다. 사전공고·본공고·발주계획 각각 413행(고정 시드 특수문자 400개 및 경계값 13개)의 공고번호·제목을 정확히 대조한다. 쉼표·따옴표·CR/LF·탭·한글/이모지·빈 값·숫자/불리언·JSON 객체를 포함한다. 첫 검사에서 Fetch UTF-8 디코딩의 선두 BOM 제거를 바이트 불일치로 판단했으며, 정상 BOM 제거만 허용하고 나머지 본문 일치를 유지하도록 수정했다. 테스트에서만 작성기/독자를 함께 사용하며 운영 모듈 의존성은 변경하지 않았다. 전체 391개 테스트 통과. 합성 입력 검증이며 운영 파일 전수 대조는 아니다.

CSV 인용 필드가 닫히지 않았거나 닫는 따옴표 뒤 구분자 없이 문자가 이어지는 경우, 행의 열 수가 헤더보다 많은 경우를 파일 오류로 처리한다. 끝 쉼표의 빈 셀 누락도 수정했다. 정상 인용 개행·기존 Excel 텍스트 강제 형식은 회귀 테스트를 유지한다. 전체 388개, 25만 행까지의 합성 부하 및 두 화면 크기 브라우저 검증 통과. 구형 파일 호환을 위해 헤더보다 짧은 행은 아직 허용하므로 모든 잘림을 검출한다고 주장하지 않는다.

내용이 있는 CSV에 해당 모드의 공고번호 열이 없거나 중복 헤더가 있으면 검색 0건으로 숨기지 않고 실패 파일로 집계한다. HTML 오류 본문을 gzip으로 정상 수신한 경우도 브라우저에서 실패 안내를 확인했다. 기존 수집기 호환성을 위해 빈 파일/BOM만 있는 파일 및 번호 열만 있는 구형 CSV는 허용한다. 전체 386개 및 두 화면 크기 브라우저 검증 통과. 모든 열/행 길이의 엄격한 검사나 선언 건수와 실제 건수의 일치 검증은 아니다.

갱신 완료 후 인덱스 재조회에서도 요청 세대를 확인해 이전 완료 처리의 늦은 성공/실패가 새 실행 UI·검색 날짜·자동 검색을 바꾸지 않게 했다. 다른 인덱스 요청에 의해 stale 처리된 조회는 갱신 건수나 자동 검색에 반영하지 않는다. 정상 완료의 날짜 갱신/조건부 재검색도 회귀 검증했다. 전체 384개 테스트와 두 화면 크기 브라우저 검증 통과. 원격 수집 실행은 없었다.

초기/갱신 후 인덱스 조회가 겹치면 마지막으로 시작한 조회만 공고·분석 목록·스키마 버전·갱신 시각을 반영한다. 이전 조회의 늦은 성공/실패는 stale 결과로 반환하며 초기 진입 경로는 해당 결과로 검색을 다시 실행하거나 화면을 비우지 않는다. 응답 역전과 이전 오류 회귀를 추가해 전체 381개 및 두 화면 크기 브라우저 검증 통과. 최신 요청 자체가 실패하면 기존 유효 목록을 유지하며, 이전 요청 결과를 임의로 대신 적용하지 않는다.

갱신 상태 조회는 running 불리언, waiting 불리언/진행 상태 일관성, 실행 번호 자료형을 확인한 뒤 처리한다. `{}`처럼 필수 상태가 없는 성공 응답을 `!state.running`으로 완료 처리하던 경로를 차단했다. 손상된 응답은 완료 처리/인덱스 재로드 없이 상태 확인 실패를 안내하며, 정상 숫자/문자열 실행 번호는 유지한다. 추가 회귀 후 전체 379개 및 두 화면 크기 브라우저 검증 통과. 원격 수집은 실행하지 않았다.

갱신 시작·초기 실행 복구·상태 폴링에 요청 세대 구분을 추가했다. 지연된 초기 조회와 이전 폴링의 성공/실패가 새 runId·UI·완료 처리를 덮어쓰지 않게 한다. 전체 377개 테스트 통과. 첫 브라우저 검증에서 요청 세대 변수의 선언이 초기 resume 호출보다 늦어 초기화 오류가 발생한 것을 확인했고, 앱 초기 상태 선언부로 이동한 뒤 두 화면 크기의 전체 흐름을 재검증해 통과했다. 실제 수집 dispatch나 원격 작업은 수행하지 않았다.

보유 데이터 갱신 시작 POST에도 30초 본문 수신 제한과 중복 진입 차단을 적용했다. 응답을 확인하지 못하면 컨트롤을 복구하되 서버 작업은 이미 시작됐을 수 있음을 표시하고, 재요청 전에 새로고침으로 상태를 확인하도록 안내한다. 자동 dispatch 재전송은 하지 않는다. 409 기존 작업의 runId 추적과 서버의 구체적 오류 설명은 유지한다. 중복·시간 초과/늦은 성공·409/404 회귀를 추가해 전체 375개 테스트와 두 화면 크기 브라우저 검증 통과. 실제 GitHub 수집 작업을 시작하거나 운영 설정을 변경하지 않았다.

일반 JSON 데이터 조회에도 본문 수신까지 30초 제한을 적용했다. 공고 인덱스·ECR 인덱스·갱신 상태 조회가 대상이며 공통 HTTP 처리기를 사용한다. 인덱스/상태 장애에는 파일 재분석이 아닌 새로고침/재로그인 안내를 표시하고 HTTP 오류는 성공 데이터로 반환하지 않는다. 자동 재전송은 하지 않는다. 전체 372개 테스트와 두 화면 크기 브라우저 검증 통과. ECR 인덱스 시간 초과는 기존의 분석 목록 보존 경로로 처리되며, 두 인덱스를 함께 기다리는 초기 로딩은 느린 보조 인덱스 때문에 최대 30초 대기할 수 있다.

인덱스의 동일 CSV 경로 중복, 경로 접두사와 다른 공고 모드, 음수/소수/문자열 건수를 거부해 중복 스캔과 잘못된 유형 분류를 예방한다. ECR 인덱스의 동일 공고 중복도 임의의 마지막 경로로 덮어쓰지 않고 목록 확인 실패로 처리해 기존 캐시를 보존한다. 모드/건수 생략 구형 항목과 정수 0건은 허용한다. 추가 회귀 후 전체 370개 및 두 화면 크기 브라우저 검증 통과. 서로 다른 CSV에 포함된 동일 공고의 중복이나 파일 내용과 선언 건수의 일치까지 검사하는 것은 아니다.

데이터 인덱스를 적용하기 전에 파일 배열·항목 경로·공고 모드·실재하는 날짜/기간 순서를 검증한다. 손상된 인덱스는 기존 fileIndex/분석 목록/갱신 시각을 변경하기 전에 거부한다. ECR 인덱스만 조회 실패 또는 형식 오류이면 공고 검색은 계속하고 기존 분석 목록을 보존하며 데이터 현황에 확인 실패를 표시한다. 유효한 빈 인덱스는 정상 교체로 취급한다. 전체 367개 테스트와 브라우저 두 화면 크기 검증 통과. 이 검증은 인덱스 형식에 대한 것이며 실제 CSV 내용·인덱스 건수의 일치나 최신성 보증은 아니다.

Worker 풀 생성 중 두 번째 이후 생성이 실패하면 이미 생성한 Worker 참조가 유실되던 자원 정리 문제를 수정했다. 생성 중 목록을 보관해 실패 시 모두 종료하고 이후 검색은 대체 경로를 재사용한다. 첫 실패·부분 실패·정상 재사용 테스트를 추가해 전체 364개 통과. 브라우저에서도 Worker 생성자를 실패 대역으로 바꾼 뒤 실제 검색을 실행해 대체 경로의 결과 복구를 두 화면 크기에서 확인했다. 이전의 단순 빈 풀 주입보다 생성 실패 복구까지 범위를 확장한 검증이며 운영 환경에서 실패를 발생시키지는 않았다.

저장 검색의 20만 건 표시 한도를 결과 묶음 추가 전에 적용한다. 이전에는 큰 CSV 또는 Worker 묶음을 모두 추가한 뒤 한도를 검사해 초과할 수 있었다. Worker 합산과 메인 스레드 대체 경로 모두 경계 회귀 테스트를 추가해 전체 351개 및 두 화면 크기 브라우저 검증이 통과했다. 한도 도달 안내는 일부 결과 생략 가능성을 명시한다. 이는 저장 검색의 표시 배열 제한이며, 원문 CSV 파싱/Worker 내부 임시 배열의 메모리 상한이나 최신 API 결과 추가분까지 포함한 전역 제한은 아니다. 한도 결과는 전체 중 최신순 상위 20만 건을 보장하지 않으므로 기간·기관 범위를 좁혀야 한다.

검색 Worker는 새 검색 시작 및 해당 검색 버전 취소 시 AbortController로 이전 동시 CSV 다운로드를 중단한다. 오래된 버전의 취소 메시지는 현재 검색에 적용하지 않으며 취소 오류를 파일 실패로 집계하거나 이전 완료 결과를 내보내지 않는다. 메인 스레드 대체 경로에도 다운로드 취소를 적용했고, 이전 검색 종료가 새 검색의 취소 제어를 지우지 않게 했다. 표시 한도 도달 시 나머지 대체 경로 다운로드도 중단한다. 두 경로의 취소 회귀 테스트를 포함해 전체 349개 통과. 브라우저에서는 실제 Worker gzip 검색 후 풀을 비워 대체 검색으로 전환해 동일 결과 복구를 두 화면 크기에서 확인했다. Worker 생성 실패 이벤트 자체를 주입한 검증은 아니며, 동기 파싱 도중 즉시 선점 취소하는 기능도 아니다.

CSV 다운로드·gzip 해제·본문 수신에는 파일당 60초 제한을 추가했다. 시간 초과 시 fetch와 압축 해제 스트림을 취소하고, 기존 검색 경로가 실패 파일 수를 표시하도록 한다. Worker와 메인 스레드 대체 경로가 같은 처리기를 사용한다. 자동 재요청은 하지 않으며 캐시 재검증 옵션은 유지한다. 헤더 무응답·본문 정지/스트림 취소·손상 gzip 테스트를 추가했고 전체 343개와 두 화면 크기 브라우저 검증이 통과했다. 전체 검색의 총시간 제한이나 메모리 상한은 아니며 동기 CSV 파싱 시간까지 중단하는 기능도 아니다.

브라우저 스모크의 검색 범위를 실제 `search-worker.js` 실행까지 확장했다. 로컬 gzip CSV 4행을 브라우저가 내려받고 압축 해제·CSV 파싱·업무/검색어/행별 기간 필터링을 수행해 정답 1행을 표시하는지 검증한다. 쉼표와 이중 따옴표가 있는 제목 보존, 실제 Worker 생성 및 CSV 요청도 확인한다. 같은 파일의 503을 주입하면 조회 실패 안내를 표시하고 수동 검색 재시도 시 결과가 복구되는 흐름이 데스크톱/모바일에서 통과했다. 전체 단위/회귀 테스트 340개도 통과했다. 소규모 고정 fixture 검증이며 운영 전체 데이터 정확성·대용량 성능·실시간 외부 API의 검증은 아니다.

검색·자연어 해석·수집 갱신의 상태 영역에 polite/atomic 라이브 영역을 지정했다. 기관명·기관 코드·프리셋·자연어 입력에 명시적 접근성 이름을 추가했다. HTML 계약 검증 2개 및 실제 브라우저에서 접근성 이름으로 자연어 입력을 찾아 조작하는 검증을 추가했다. 전체 테스트 333개와 두 화면 크기 검증 통과. 실제 화면 낭독기 음성 출력, 전체 WCAG 적합성, 색 대비 전수 검증을 완료했다는 의미는 아니다.

검색 조건 적용 전에는 달력상 존재하는 날짜, 시작/종료일 쌍과 순서, 공고 모드·업무 구분 열거값, 검색어·설명·기관·안내의 자료형 및 느슨한 기관 일치의 불리언 값을 검증한다. 잘못된 값은 조용히 다른 조건으로 바꾸지 않고 응답 전체를 거부해 기존 컨트롤을 보존한다. 윤년 정상 날짜와 기간 미지정 응답도 검증했다. 전체 테스트 331개 통과. 브라우저 검증에도 고급검색 메뉴 진입, 정상 응답 적용, 잘못된 날짜 응답 후 기존 검색어/기간 보존을 추가했으며 두 화면 크기에서 통과했다. 첫 브라우저 실행은 테스트가 메뉴를 열지 않아 실패했고, 실제 메뉴 진입 동선으로 수정 후 재검증했다.

자연어 검색은 공통 HTTP 처리기를 사용해 응답 본문 수신까지 60초로 제한한다. 시간 초과는 서버 추론 취소를 보장하지 않으며 자동 재전송하지 않는다. 파일 재개 안내 대신 일반 검색 대안을 표시한다. JSON 파싱 실패·비정상 최상위 값·필터 누락·기관/안내 배열 형식 오류는 기존 조건에 적용하지 않는다. 타임아웃 뒤 늦은 성공 응답 무시와 재시도 가능 여부를 포함한 추가 검증 후 전체 테스트 326개 및 데스크톱/모바일 브라우저 검증이 통과했다. 실제 모델 호출 없이 검증했다.

자연어 검색 버튼이 비활성화되어도 입력창 Enter로 추가 요청을 보낼 수 있던 경로를 요청 단위 잠금으로 차단했다. 해석 대기 중 질의·검색어·기간·업무 구분·기관·기관 느슨한 일치·공고 모드 또는 검색 실행 버전이 바뀌면 이전 응답을 적용하지 않는다. 오래된 실패 응답도 현재 검색 실패로 표시하지 않는다. 자동 재전송은 하지 않는다.

실제 앱 함수를 실행하는 회귀 테스트 6개를 추가했고 전체 322개가 통과했다. 이 검증은 UI 요청 순서와 적용 조건에 대한 것이며, 실제 모델의 검색 조건 해석 정확도나 서버의 중복 요청 제한을 증명하지 않는다. 대기 중 요청의 서버 추론은 취소하지 않는다.

### 저장 ECR 조회 장애 복구

빈 ECR 상세 결과는 저장된 `verified: true`와 무관하게 ‘추출 결과 없음 — 요구사항이 없다는 뜻은 아닙니다. 원문 확인 필요’로 표시한다. 장비 요약의 빈 종류에도 원문 확인을 안내해 기존 CSV 0건 경고와 의미를 맞췄다. 저장 데이터의 검증 플래그 자체를 수정하는 것은 아니다. 회귀 2개 추가 후 전체 361개와 긴 결과를 포함한 두 화면 크기 브라우저 검증 통과.

긴 ECR 결과 브라우저 검증: 서버/스토리지 100개 카드와 공백 없는 긴 명칭·값·근거를 합성해 공통 검증→상세 표→장비 카드 렌더링을 실행한다. 두 화면 크기에서 100개 카드 보존, 모달 가로 넘침 없음, 근거 details의 키보드 펼침을 확인한다. 로컬 Edge 첫 관측은 렌더링+레이아웃 1440px 92ms, 390px 66ms였으며 실제 모바일 기기 성능 기준은 아니다. 캡처는 무시되는 `test-results/ecr-long-*.png`에 생성한다. 실제 문서 필드 정확성·실제 모바일·스크린리더 검증을 대신하지 않는다.

로컬 workerd가 생성한 실제 결과 객체를 공통 구조 검증 및 장비 요약 렌더러로 넘기는 통합 검증을 추가했다. 최초 응답과 R2 저장 조회의 전체 객체 일치, 메모리 근거 표시, 완전성 비보증 안내를 확인한다. 완료 구간 재요청은 추가 추론 없이 동일한 규격/근거/경고를 다시 합치며, 이때 `analyzedAt`은 재합성 시각으로 갱신된다. 처음 전체 객체 동일 비교는 이 시각 차이로 실패했고, 최초 저장의 정확한 일치와 재합성의 내용 보존/유효 시각을 분리해 검증했다. CSV의 분석일 역시 최초 모델 추론 시각이나 원문 최신성을 뜻하지 않는다. 로컬 런타임 외부 요청 0건 및 전체 359개 테스트 통과. 모델 자체는 고정 응답 대역이므로 실제 모델 정확도 검증은 아니다.

공통 ECR 구조 검증을 저장 조회·새 분석 완료·CSV 내보내기에 적용했다. 항목 객체, 규격/장비 배열, 경고/누락/출처 목록, coverage 배열과 verified 불리언을 확인하며 손상된 중첩 데이터는 캐시에 기록하기 전에 거부한다. 구형 결과의 선택 필드 누락과 정상 0건 배열은 허용한다. 이는 소비 경로의 구조 안전성 검증이며 값의 의미·전체 원문 정확성 검증이나 모든 스칼라 필드의 엄격한 스키마 검증은 아니다. 전체 359개 회귀 테스트와 두 화면 크기 브라우저 검증이 통과했다.

ECR 원문 상세 행에 native button을 추가해 키보드 Enter/Space로 펼치고 접을 수 있게 했다. 버튼은 요구사항 번호·명칭을 접근성 이름에 포함하고 `aria-controls`/`aria-expanded`로 대상과 상태를 제공한다. 기존 행 클릭도 유지하며 두 경로가 동일한 상태를 갱신한다. 실제 브라우저에서 Enter 펼침·Space 접힘·행 클릭의 상태/가시성을 두 화면 크기로 검증했고 전체 356개 회귀 테스트도 통과했다. 실제 화면 낭독기 음성 출력 검증은 별도 미완료다.

ECR CSV 내보내기도 저장 조회의 30초 요청 제한을 사용한다. `ecr` 배열 누락은 0건 분석으로 대체하지 않고 전체 내보내기를 중단한다. 대상이 없는 경우 헤더만 있는 CSV를 생성하지 않는다. 시작 시점의 대상·제목·저장 경로를 복사해 내보내기 도중 검색 목록 변경에 영향을 받지 않게 했다. 두 공고 중 두 번째 조회 실패 시 부분 파일을 만들지 않는 검증과 대상 변경 회귀 검증을 포함해 전체 340개 테스트가 통과했다. 브라우저 두 화면 크기에서도 CSV 다운로드 검증이 통과했다. 저장 경로의 내용 자체가 동시 갱신되는 경우까지 동일 시점 스냅샷을 보장하는 것은 아니다.

클라우드 저장 결과와 404 뒤 기존 저장 경로 조회는 각 요청의 본문 수신까지 30초 제한을 적용한다(순차 대체 경로까지 실행하면 총 대기 시간은 최대 약 60초). 자동 재요청이나 재추론하지 않는다. 조회 장애 안내는 파일 재업로드 대신 저장 결과 재조회를 권한다. `ecr` 배열이 없는 응답은 현재 분석과 목록 캐시에 기록하지 않는다. 타임아웃 이후 늦은 응답 무시, 수동 재조회 성공, 기존 경로 성공 및 본문 지연을 검증했다. 전체 테스트 337개와 데스크톱/모바일 브라우저 검증 통과. 개별 저장 ECR 항목의 전체 스키마 검증까지 추가한 것은 아니다.

### AI 전용 잠금의 서버 측 토큰 취소

AI 잠금 조회·해제·취소 요청은 본문 수신까지 30초로 제한한다. 시간 초과 시 입력 컨트롤을 복구하되 분석은 비활성화하고 자동 재전송하지 않는다. 해제 응답 유실 시 서버 잠금 재시도 버튼을 제공한다. 취소는 HTTP 성공만으로 완료 처리하지 않고 `unlocked: false` JSON도 확인한다. 늦은 성공 응답·본문 지연·손상된 성공 응답 회귀 검증을 추가해 전체 329개 및 브라우저 2개 화면 크기 검증이 통과했다.

브라우저 요청 중단은 서버 작업 취소나 쿠키 발급 취소를 보장하지 않는다. 이 변경은 확인되지 않은 권한으로 화면에서 추가 분석을 시작하지 않게 하는 것으로, 쿠키를 받지 못한 발급 토큰까지 전역 취소하는 기능은 아니다. 운영 환경이나 실제 AI 호출은 사용하지 않았다.

운영 배포 없이 로컬 검증을 계속한다는 사용자 선택에 따라 원격 AI·운영 R2를 호출하지 않았다. 사이트 로그아웃 통합 후 단위/회귀 테스트 316개, 로컬 workerd + R2의 취소 토큰 재사용 거부, 브라우저 2개 화면 크기의 흐름 검증을 통과했다. 확정 라벨 문서 2건의 번호 선별 검증도 통과했으며, 실제 모델 필드 추출 품질은 별도 미검증이다.

기존 AI 전용 DELETE는 브라우저 쿠키만 지웠다. 이제 유효한 서명 토큰의 nonce에 대한 취소 표식을 R2에 먼저 저장하고 성공한 뒤 쿠키를 지운다. 이후 같은 쿠키를 재전송해도 AI 사용 권한을 거부한다. 취소 표식 조회가 실패하면 권한을 허용하지 않는다. 저장 실패는 503이며 쿠키를 유지해 취소 재시도가 가능하게 하고, 화면에는 ‘서버 잠금 다시 시도’ 버튼을 제공한다.

취소는 제출한 토큰에만 적용한다. 다른 로그인에서 별도 발급한 토큰이나 이미 실행 중인 요청을 취소하지 않는다. 사이트 로그아웃도 동일한 AI 서버 취소 경로를 사용한다. 기존 `/__gate/logout` 링크는 API 범위 쿠키를 받을 수 있는 `/api/logout`으로 이동한다. 취소 실패 시 사이트 조회 쿠키만 삭제하고, AI 쿠키는 취소 재시도를 위해 유지하며 503과 재시도 링크를 표시한다. 사이트 조회 쿠키 자체의 복사본까지 서버에서 취소하는 것은 아니다. 전체 AI 권한을 즉시 비활성화해야 하면 운영자의 시크릿 회전/비활성화가 필요하다.

취소 표식은 `_meta/ai-access/revoked/YYYY-MM-DD/<nonce>.json`에 만료 시각만 저장하며 쿠키 서명·비밀번호는 저장하지 않는다. 만료된 표식의 자동 정리는 아직 없고, 표식 보관량을 운영 점검 대상으로 남긴다. 유효 쿠키 확인마다 R2 조회 1회가 추가된다. 과거의 ‘쿠키만 삭제한다’는 기록은 이 변경 전 상태다.

전체 312개 테스트 통과. workerd+로컬 R2 검증에 실제 토큰 취소 뒤 같은 쿠키로 step을 재전송해 403과 추가 추론 0회를 확인하는 경로를 추가했다. 운영 R2·도메인 검증은 별도다.

이번 런타임 검증의 첫 실행은 로컬 undici 연결이 ECONNRESET으로 종료됐다. 종료를 확인한 뒤 다시 실행해 통과했으나 최초 연결 종료 원인은 확정하지 못했다. 검증 도구에는 실패를 숨기는 자동 재시도를 넣지 않았다. 브라우저 두 크기 검증은 통과했다.

### 내보내기의 검증 정보 보존

ECR CSV의 기존 열 순서를 유지하고 미추출 번호, 제외/불확실 사유, 검증 오류·경고, 번호 대조 상태, 분석일, 모델, 출처를 뒤에 추가했다. 0건 분석도 ‘추출된 ECR 없음’ 행을 남기며 원문 확인 필요로 표시한다. 한 공고 조회가 실패하면 일부 결과만 성공 파일로 저장하지 않는 기존 동작을 회귀 테스트로 고정했다. 셀 수식 보호와 CSV 이스케이프는 공통 직렬화기를 그대로 사용한다.

전체 309개 테스트가 통과했다. 데스크톱·모바일 크기 실제 브라우저에서 메뉴의 ECR 내보내기를 눌러 다운로드 스트림의 미추출 번호·0건 안내·검증 경고를 확인했다. 외부 API는 fixture이며 실제 운영 데이터 다운로드 검증은 아니다. 새 열이 추가되므로 고정 열 개수를 가정한 외부 연동은 점검해야 한다.

### 저장 결과 조회의 오래된 응답 차단

공고 객체 일치 검사만으로는 같은 공고의 겹친 조회나 재진입, 조회 도중 시작한 새 분석을 구분하지 못했다. 저장 결과 조회에 순서 번호와 분석 작업 번호를 함께 연결했다. 최신 요청·작업이 아닌 응답은 현재 분석 객체, 표시 건수, 결과 화면을 변경하지 않는다. 닫힌 상태에서는 요청을 시작하지 않는다.

겹친 조회의 역순 성공, 새 분석 후 도착한 이전 저장 결과, 같은 공고 재진입 후 늦은 오류, 닫힌 상태를 실제 화면 함수 기반 모형으로 검증했다. 전체 306개 테스트와 브라우저 두 크기 검증 통과. 원격 저장 결과의 진위나 필드 정확도를 검증하는 변경은 아니다.

### Worker 런타임과 로컬 R2 통합 검증

`npm run test:runtime`을 추가하고 품질 CI에 연결했다. 실제 Worker 코드를 esbuild로 메모리 번들링하고 Wrangler와 같은 버전의 Miniflare/workerd에서 실행한다. 로컬 비영속 R2를 사용하며 AI만 고정 응답으로 주입한다. 외부 fetch는 차단한다. 게이트 로그인, AI 잠금 전 실행 차단, 잠금 해제, TXT 업로드, 규격 추출·번호 대조, R2 저장, 사이트 조회 권한의 결과 열람, 동일 작업 캐시 재사용, 동시 step의 단일 추가 추론, R2 ETag 조건부 쓰기가 통과했다.

추론 횟수는 호출마다 고유 R2 키를 남겨 계산한다. 단순 read-modify-write 카운터의 경쟁으로 중복 호출이 숨겨지지 않게 했다. 외부 요청은 0건이며 종료 시 런타임을 dispose한다. 개발 의존성 버전은 현재 Wrangler의 하위 패키지와 맞춰 명시 고정했다. 로컬 302개 테스트도 통과했다.

이는 메모리 Map 모형보다 실제 바인딩에 가까운 검증이지만 운영 R2의 지역 간 지연·장애, Cloudflare CPU 한도, PDF 변환·실제 모델 품질을 대신 검증하지 않는다. 원격 운영 검증은 여전히 승인 및 별도 실행이 필요하다.

### 변경마다 실행하는 품질 워크플로

`service-quality` GitHub Actions 워크플로를 추가했다. push·pull_request·수동 실행을 지원하며 저장소 읽기 권한만 요청하고 checkout 자격증명을 보존하지 않는다. 사용 액션은 공식 저장소 v7 태그에서 확인한 커밋으로 고정했다. `npm ci`, `npm test`, high 이상 의존성 검사, Wrangler dry-run, 설치된 테스트 Chromium의 fixture 기반 브라우저 회귀를 실행한다. Cloudflare·수집 시크릿 및 운영 배포 명령은 없다. 브라우저 실패 지점의 화면 캡처도 남겨 7일 artifact로 보관한다.

로컬 302개 테스트 및 두 브라우저 크기 검증이 통과했다. 워크플로 안전 경계의 정적 테스트는 GitHub 러너 실행 자체를 검증하지 않는다. 아직 원격에 push하거나 Actions를 실행하지 않았으므로 실제 Ubuntu CI 성공은 미확인이다. 브랜치 보호·필수 체크는 저장소 설정에 별도로 지정해야 하며 자동 변경하지 않았다. 저장소 밖 실문서 원본을 CI에 올리지 않으므로 `test:selection`은 별도 품질 관문으로 남는다.

### 외부 링크 실행 경로 제한

첨부파일과 상세 링크에 HTTP(S) URL 검증을 적용했다. 실행 스킴, 상대·프로토콜 상대 주소, 제어문자 포함 주소, 사용자정보 포함 주소와 잘못된 URL은 링크로 만들지 않는다. 첨부의 제외 건수와 상세 링크 비활성 사유를 표시하며 전체 다운로드도 같은 필터를 적용한다. 정상 링크의 쿼리 문자열은 변경하지 않고, 원본 수집 데이터도 수정하지 않는다.

스킴·제어문자 경계, 깨진 첨부 구조, 전체 다운로드 경로를 테스트했고, 실제 브라우저 fixture에도 잘못된 URL을 넣어 링크가 생성되지 않는지 확인했다. 전체 300개 테스트 및 브라우저 두 크기 검증 통과. HTTP(S) 허용은 해당 외부 사이트나 다운로드 파일의 안전성을 보증하는 검사가 아니다.

### 규격 근거의 요구사항 소속 검증

다른 ECR의 메모리나 SFR의 수치를 현재 장비 규격으로 반환해도 기존 파서는 원문에 있다는 이유로 확인 처리하는 문제를 실패 테스트로 재현했다. 표 선별과 같은 번호 경계 탐지기를 재사용하되 검증 시에는 입력 문자 위치를 바꾸지 않는다. 줄 번호 근거가 다른 요구사항에 속하거나 여러 번호에 걸치면 제외하고 사유를 남긴다. 구형 문자열 근거가 다른 번호에서만 발견돼도 제외한다. 번호 앞 공통 본문처럼 적용 소속이 불명확한 줄은 확인 필요로 표시한다.

이 검증은 번호 경계를 식별할 수 있는 범위에 한정된다. 같은 번호 안의 여러 장비 구분, 표 경계 오인식, 공통 조건의 실제 적용 여부, CPU·메모리 등의 의미 해석까지 검증 완료로 간주하지 않는다. 경계가 없는 구간은 기존 원문 존재 대조이며 결과 전체의 verified는 여전히 false다.

전체 294개 테스트, 실문서 번호 선별 관문, 브라우저 두 크기 검증이 통과했다. 작업 판은 cloud-v4로 올려 이전 파서 결과가 새 검증 결과처럼 재사용되지 않도록 했다. 기존 저장 결과는 자동 재검증하지 않으며 새 판 재분석에는 사용량이 발생할 수 있다.

### 로컬 실문서 번호 선별 평가

2026-09-25 저장소 옆 `gong-go-eval`의 실제 텍스트 3개로 기존 라벨을 수정하지 않고 평가했다. 수정 전 확정 라벨 문서의 33개 대상 번호는 모두 선별됐으나 `4dae.txt`에서 ‘장비 라이선스’ ECR-002가 추가로 선별됐다. 명칭 전체가 라이선스 전용 표인 경우만 제외하도록 수정했고, ‘서버(라이선스 포함)’·‘라이선스 관리 서버’ 및 본문의 라이선스 조건은 유지하는 회귀 테스트를 추가했다.

수정 후 양산선은 대상 29/29, 4대보험은 4/4 적중, 두 문서 모두 번호 누락·오검출 0건이다. SR-MaaS는 접두어 기반 추정 라벨 20/20으로 참고 결과일 뿐 확정 라벨 성과에 합산하지 않는다. 원문은 새로 저장소에 복사하지 않았고 원격 AI도 호출하지 않았다. 이 표본 결과를 일반 RFP 전체나 필드별 추출 정확도로 일반화하지 않는다.

`npm run test:selection`은 확정 표본이 없거나 번호 누락·오검출·미라벨·분할 실패가 있으면 실패한다. 비용 출력은 고정 구간당 가정이며 실제 모델 사용량·재시도·변환을 반영하지 않는다는 안내를 추가했다. 전체 290개 테스트와 데스크톱·모바일 크기 브라우저 회귀가 통과했다.

표 선별 방식 변경에 따라 작업 키 버전을 cloud-v3으로 올렸다. 새 업로드는 새 구간을 생성하므로 이전 판의 완료 구간을 자동 승계하지 않는다. 기존 저장 결과를 삭제하지는 않지만, 새 판으로 재분석하면 AI 사용량이 발생할 수 있다.

### ECR 대화상자 키보드 동선

공고 상세 창에 `role=dialog`, `aria-modal`, 제목·설명 연결을 추가했다. 열 때 닫기 버튼으로 초점을 옮기고 배경 `.app`을 inert로 만든다. 현재 보이는 활성 컨트롤만 대상으로 Tab·Shift+Tab을 창 안에서 순환시키며 Esc로 닫으면 진입 버튼으로 초점을 돌린다. 진입 버튼이 렌더링 교체로 사라졌다면 현재 공고 유형 버튼으로 돌아간다.

브라우저 회귀에 실제 키보드 입력을 추가했다. 1440px와 390px에서 최초 초점, 역방향·정방향 순환, Esc 종료, 배경 활성 복구, 진입 버튼으로 복귀, Enter 재진입을 확인했다. 기존 287개 테스트와 브라우저 두 크기 검증 통과. 스크린리더 실사용 검증이나 접근성 전체 적합성을 주장하지 않는다. 참고: [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

### 실제 브라우저 회귀 실행

`npm run test:browser`를 추가했다. Playwright Core로 설치된 Edge를 headless 실행하며, 실제 HTML/CSS/JS와 fixture 공고를 사용한다. 외부 통신은 모두 차단하고 알려진 정적 파일 및 API 테스트 응답만 제공한다. 1440×1000과 390×844에서 ECR 진입 버튼, 잠금/해제, 파일 선택·전송, 진행 중 중지, 같은 파일 재개, 미추출 번호 표시, 다시 잠그기를 검증했다. 페이지 스크립트 오류 및 미등록 요청 0건, 모달의 화면 너비 내 배치를 확인했다. 390px 스크린샷도 직접 검토했다. 화면 캡처는 `test-results/`에 저장한다.

이는 실제 브라우저의 프런트엔드 회귀 검증이며, 테스트 응답을 쓰므로 운영 API 인증·R2·모델을 포함한 통합 검증이나 실제 모바일 기기 검증으로 주장하지 않는다. 검색 결과는 fixture를 렌더링하므로 검색 데이터 파이프라인 검증도 별도다.

의존성 검사에서 기존 Wrangler→Miniflare→sharp 경로의 high 경고 3건을 확인했다. Wrangler를 4.120.0에서 4.140.0으로 명시적으로 갱신하고 잠금 파일을 반영했다. 갱신 후 npm 검사상 취약점 0건, 기존 287개 테스트 및 두 브라우저 크기 회귀가 통과했다. 취약점 0건은 검사 시점에 알려진 의존성 경고가 없다는 뜻이지 전체 서비스 보안 보증이 아니다.

### 분석 통신 시간 제한과 오류 복구

ECR 업로드·구간 요청은 응답 본문 수신까지 포함해 210초로 제한한다. 제한 시간이 지나면 브라우저의 수신을 중단하고 처리 중 상태를 해제한다. 이는 원격 작업 취소나 비용 환급을 보장하지 않는다. 결과가 불확실한 요청을 자동 재전송하지 않으며, 같은 파일로 재시작할 때 서버의 완료 캐시와 잠금을 이용한다.

HTML 오류 페이지, 잘못된 JSON 형태, 비JSON 로그인 만료 응답, 네트워크 오류에는 원문 오류 페이지를 노출하지 않고 복구 안내를 제공한다. 정상 JSON 오류의 잠금 상태·참조 번호는 기존 처리로 전달한다. 응답 없음, 본문 정지, 오류 HTML, JSON 형태 및 로그인 만료, 본문·구조화 오류 보존, 모듈 로드 순서, 실패 후 입력 복구 테스트를 추가했다. 전체 287개 테스트 통과. 이 시간 제한은 ECR 실행 경로에 적용하며 사이트 전체 통신을 일괄 변경하지 않았다.

### 분석 중지와 화면 이동

분석 화면에 ‘추가 분석 중지’ 버튼을 추가했다. 닫기, 다른 공고 열기, ECR 이외 탭 선택도 현재 작업을 무효화한다. 같은 공고 객체를 빠르게 다시 열더라도 이전 작업의 다음 구간을 요청하지 않는다. 중지 후 늦은 진행 응답이 중지 안내를 덮어쓰지 않으며, 진행 중인 요청이 끝날 때까지 새 분석은 허용하지 않는다. 그 뒤 같은 파일을 다시 제출하면 기존 서버 캐시를 재사용할 수 있다.

이미 전송한 변환·추론은 취소하거나 환불하지 않는다. 응답 대기 제한은 위의 ‘분석 통신 시간 제한과 오류 복구’에서 추가했다. 변환 중 중지, 구간 진행 중 중지 및 중복 실행 차단, 닫은 뒤 같은 공고 재진입, 중지 후 새 작업 시작을 실제 화면 핸들러 기반 모형 테스트로 검증했다. 이 단계에서 전체 280개 테스트가 통과했다.

### 화면 잠금 요청의 순서 보장

AI 상태 조회 응답은 시작 당시의 화면 상태 버전이 여전히 유효할 때만 반영한다. 잠금/해제 변경 중에는 입력과 변경 버튼을 비활성화하고 중복 변경·조회 요청을 보내지 않는다. 잠금 클릭은 즉시 화면의 분석 권한을 내려 다음 분석 구간 요청을 막는다. 이미 서버로 전송한 요청의 실행·과금을 취소한다고 안내하지 않는다.

실제 `app.js` 핸들러를 DOM·통신 모형으로 실행해 잠금 뒤 도착하는 오래된 조회 성공, 잠금 해제 뒤 도착하는 오래된 조회 실패, 중복 제출, 변경 실패 시 복구, 역순 조회 응답을 검증했다. 전체 276개 테스트 통과. 다른 탭의 상태 동기화와 실제 브라우저 상호작용 검증을 대신하지는 않는다.

### AI 인증 문자열 구분과 쿠키 전환

실패 테스트로 암호 끝 NUL 추가/제거의 동등 취급, NUL을 추가한 암호 변경 후 쿠키 유지, 서로 다른 고립 UTF-16 surrogate의 동등 취급을 재현했다. 이 문제는 평문 암호를 직접 HMAC 키로 사용하고 UTF-8 변환 시 정보가 소실되는 경계에서 발생한다. HMAC의 짧은 키 zero padding은 [RFC 2104 §2](https://www.rfc-editor.org/rfc/rfc2104.html#section-2)에 정의되어 있다.

이제 JSON 문자열 표현으로 문자 구분을 보존한 후 도메인이 구분된 SHA-256 고정 길이 키를 사용한다. 서명 메시지는 v2로 전환하며, 이전 v1 쿠키를 승계하지 않는다. 배포 시 사용자에게 AI 전용 비밀번호 재입력이 필요하다는 점을 안내한다. 사이트 조회 인증과 저장 결과는 유지된다. 이는 암호의 추측 저항성을 높이는 느린 비밀번호 해싱이나 서버 측 세션 취소 기능을 추가한 것은 아니다. 기존 입력 시도 제한과 30분 만료는 유지한다.

재현 테스트 3개가 수정 후 통과했고, 정확한 특수문자 암호의 성공 경로와 v1 쿠키 거부를 추가했다. 전체 271개 테스트 통과.

### AI 잠금 입력 경계 보강

암호 설정과 제출의 16~512자 정책은 유지한다. 요청 본문은 4KB까지 받아 최대 길이 문자열을 JSON으로 이스케이프해도 제출할 수 있게 했다. 잘못된 JSON·비객체 본문·크기 초과는 400, 저장소 장애는 503으로 구분하며 두 경우 모두 쿠키를 발급하지 않는다. 잘못된 시도에도 기존 횟수 제한은 적용된다. 설정이 유효하지 않으면 화면에 허용 길이를 안내한다.

이스케이프된 최대 길이 암호 인증과 오류 응답 구분을 추가 검증했다. 전체 266개 테스트 통과. 이는 잠금 토큰의 서버 측 즉시 취소 기능을 추가한 것은 아니며, 기존 30분 서명 쿠키 정책은 유지된다.

1. 실제 RFP 표본별 ECR 선별 재현율·규격 누락률: 표본 정답과 비교하고, 미검증 결과를 검증 완료로 표시하지 않는다.
2. 실제 브라우저에서 모바일 업로드, 잠금, 분석 재개, 긴 표 탐색, CSV 내보내기 동선을 확인한다.
3. 대형 문서 변환·추론·병합의 원격 지연과 CPU 사용을 측정한다. 무료 한도 내 실제 배포 환경 검증은 별도다.
4. R2와 외부 AI 사이에는 트랜잭션이 없다. 모델 호출 후 결과 저장 자체가 실패하거나 잠금 만료 뒤 요청이 복구되면 정확히 한 번 실행을 보장하지 못한다. 현재 보강을 완전한 중복 과금 방지로 설명하지 않는다. 장기적으로 작업 소유권과 결과 커밋을 하나의 원자적 상태로 관리할 설계를 검토한다.
5. 잠금 해제 실패와 정산 실패 로그를 운영에서 점검한다. 원문·쿠키·비밀번호는 기록하지 않는다. 정산 실패 시 예약액은 보수적으로 남고 자동 사후 환급은 구현하지 않았다.
6. CSV 수식 보호는 직접 다운로드 파일에 적용한다. 스프레드시트에서 다시 저장하거나 다른 프로그램으로 재가공한 파일의 안전성을 보장하지 않는다.

기존 `ecr-audit.md`는 감사 시점의 관찰 기록이다. 이후 수정 여부는 현재 코드와 회귀 테스트로 확인한다.
