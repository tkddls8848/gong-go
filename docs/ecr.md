# ECR 사용과 검증

운영 구현은 [src/ecr.js](../src/ecr.js), 화면 흐름은 [public/ecr-ui.js](../public/ecr-ui.js)에 있습니다.

## 첨부·ECR 파이프라인

ECR 분석 형식 v2는 서버·스토리지·스위치별 `장비요약`을 담습니다. 랙(RACK), UPS, PC,
소프트웨어, 회선·기반시설, 여러 장비를 묶은 보안장비 표는 분석 대상이 아닙니다.
방화벽·웹방화벽처럼 규격을 적은 단품 표는 대상입니다. ECR 탭 상단에서 장비별 규격,
수량·적용 조건, 근거 문장과 전체 ECR 원문을 볼 수 있습니다. Raw/Usable, 장비당/전체,
이상/이하 표현은 원문 그대로 유지하며 합산하거나 추정하지 않습니다. 미기재는 추출값이 없다는 뜻입니다.
구형 결과는 재분석 안내를 표시합니다.

**운영 분석은 Cloudflare Worker에서 수행합니다.** 본공고의 ECR 규격 탭에서 PDF·Markdown·TXT를
올리면 `/api/ecr`이 기존 `AI` 바인딩의 `@cf/qwen/qwen3-30b-a3b-fp8`을 호출합니다.
별도 LLM API 키, 로컬 Ollama 서버, 분석용 PC가 필요하지 않습니다. PDF는 `AI.toMarkdown`으로
원격 변환합니다. HWP/HWPX는 PDF로 저장한 후 올려야 하며 스캔 PDF의 OCR은 지원하지 않습니다.
파일은 8MB까지 받습니다. 길이는 모델에 보낼 분량, 즉 선별한 상세 표의 합계로 재며 12만 자까지
허용합니다. 상세 표를 찾지 못한 문서는 전체 길이로 잽니다(원문 자체는 60만 자까지). 새 작업은 `ECR-001`, `장비-001`처럼 번호가
붙은 상세 요구사항 표를 선별해 표별 최대 2,400자(600자 겹침)로 분석합니다. 목차·총괄표의
이름 나열, 다른 종류의 요구사항은 제외합니다. 소프트웨어·PC·UPS 표도 같은 "시스템 장비구성
요구사항"으로 분류되고 CPU·메모리를 적으므로 분류로는 갈리지 않습니다. 대신 명칭으로 거르되,
이름이 걸려도 꼬리가 서버·스토리지·스위치면 남깁니다(`NMS/SMS서버`는 남고 `NMS/SMS`는 빠집니다). `보안장비 구성`처럼 묶음을 가리키는 표와 회선·기반시설 표는
명칭을 읽었고 명칭 어디에도 서버·스토리지·스위치가 없을 때만 뺍니다(묶음 표 안의 VPN관리서버도 함께 빠집니다).
`방화벽(UTM)`·`웹방화벽`처럼 장비 단품의 규격 표는 남깁니다. 명칭을 못 읽은 표에는 적용하지 않습니다. 선별은 규격을 놓치는 것보다 더 담는 쪽을 택합니다. 상세 표를 찾지 못하면 기존 5천 자 전체 문서
분할로 돌아갑니다. 최대 33구간이며 초과 시 문서를 나누라는 안내를 표시합니다. 이 상한은
임의값이 아닙니다 — 마지막 구간 요청 하나가 구간 수만큼 R2를 읽어 결과를 합치므로, 무료
Worker의 요청당 subrequest 한도 50에서 예산 재시도와 구간 표식 몫을 빼고 역산한 값입니다.

제안요청서는 요구사항 표 둘을 한 쪽에 좌우로 싣기도 합니다. 쪽마다 늘 비어 있는 칸을 찾아
세로로 갈라 위아래로 편 뒤에 선별합니다. 번호 칸이 두 열로 갈리고, 자른 양쪽에 번호와 ID가
모두 남을 때만 두 표로 봅니다. 여백을 가로지르는 줄은 자르지 않습니다.

`node tools/eval-selection.mjs`는 실문서를 사람이 분류한 정답과 대조해 재현율을 표로 냅니다
(텍스트는 저장소 밖 `gong-go-eval/`에 둡니다). 2026-09-25 기준 본공고 3건에서 재현율은
모두 100%이고 오검출은 57건 중 1건입니다. 2026-09-30에 한국투자공사 가상화 인프라 증설과 수협 재해복구센터
구축 2건(`kic.txt`, `suhyup.txt`)을 추가했습니다. 로컬 텍스트 추출 기준으로 두 건 모두 재현율 100%, 오검출 0건입니다. 예약은 구간당 약 142뉴런(출력 한도 기준)으로
잡지만, 공급자가 사용량을 알려주면 차액을 장부에서 되돌리므로 실제 소모는 그보다 훨씬
적습니다. 되돌릴 근거가 없으면 예약을 그대로 두어 초과 사용 쪽으로 기울지 않습니다.

표 선별이나 구간 나누기를 고칠 때는 `src/ecr.js`의 `VERSION`을 올려야 합니다. 작업 키에
들어가는 값이라, 올리지 않으면 같은 파일을 다시 올려도 예전 방식으로 자른 구간을 그대로
재사용해 고친 것이 반영되지 않습니다.
기존 저장 작업은 구간 번호와 완료 결과를 유지하면서 상세 표가 있는 구간부터 처리합니다.
모델은 규격·근거 문장을 반복 생성하지 않고 원문 줄 범위만 반환하며, 서버가 그 범위에서
값과 근거를 복원합니다. 출력이 잘린 구간만 최대 3단계로 다시 나누고, 하위 구간도 저장해
재개 시 재사용합니다. 호출마다 기존 예산·잠금 검사를 적용합니다.
선별 분석에서 번호 없는 본문·별첨은 제외될 수 있습니다. 구간 경계 조건과 ECR 총괄표 대비 누락은 사람이 확인해야 하므로
문서 전체를 자동 검증 통과로 표시하지 않습니다.

**진입로:** 본공고 조회 결과의 사업명 옆 **ECR 분석** 버튼을 누르면 분석 탭이 바로 열립니다.
사업명을 눌러 상세창에서 ECR 분석 탭을 선택해도 됩니다. 사전공고·발주계획은 현재 분석 대상이 아닙니다.

**분석 전용 잠금:** 사이트 조회 암호와 별도로 `AI_ANALYSIS_PASSWORD` Worker Secret을
16~512자로 등록해야 합니다(문자열 길이 기준). 이 값이 없거나 허용 길이를 벗어나면 AI 호출은 기본 차단됩니다. Cloudflare의
`gong-go` Worker 설정에서 Secret으로 등록하거나, 본인의 대화형 터미널에서
`npx wrangler secret put AI_ANALYSIS_PASSWORD`를 실행해 입력합니다. `.env`에만 넣어서는 배포본에 적용되지 않습니다.

AI 인증 v2 적용 배포 시 기존 AI 잠금 해제 쿠키는 무효화됩니다. 전용 비밀번호를 다시 입력하면 됩니다.
사이트 조회 로그인은 이 변경으로 삭제되지 않습니다.

‘AI 분석 다시 잠그기’는 해당 AI 쿠키의 서버 권한도 취소합니다. 저장 실패 시 성공으로
표시하지 않으므로 ‘서버 잠금 다시 시도’를 이용하세요. 다른 로그인에서 발급된 쿠키나
이미 진행 중인 분석을 취소하는 기능은 아닙니다. 전체 권한 차단은 운영자가 전용 시크릿을 회전해야 합니다.

**화면 회귀 검증:** `npm run test:browser`는 설치된 Microsoft Edge를 headless로 실행해
데스크톱·모바일 크기의 ECR 진입, 잠금, 파일 업로드, 중지, 재개와 누락 표시를 확인합니다.
Edge가 없는 환경에서는 `BROWSER_CHANNEL=chrome` 등 설치된 채널을 환경 변수로 지정하세요.
모든 통신은 테스트 응답으로 대체하므로 원격 AI를 호출하지 않습니다. 화면 이미지는
`test-results/`에 저장되며 Git에서 제외됩니다. 실제 계정 인증·원격 모델·실기기 검증을 대신하지 않습니다.

**실문서 선별 검증:** `npm run test:selection -- <텍스트 디렉터리>`로 실행합니다.
기본 디렉터리는 저장소 옆 `gong-go-eval`입니다. 원문 파일은 저장소에 포함하지 않습니다.
확정 라벨 문서가 없거나 번호 누락·오검출·미라벨·분할 실패가 있으면 종료 코드 1을 반환합니다.
추정 라벨은 참고 출력만 하며 확정 정확도 통과의 근거로 쓰지 않습니다.

**자동 품질 검사:** `.github/workflows/quality.yml`은 push·PR·수동 실행 시
잠금 파일 기반 설치, 단위 테스트, high 이상 의존성 경고 검사, Worker dry-run,
Chromium 데스크톱·모바일 크기 검증을 실행합니다. 운영 시크릿과 배포는 사용하지 않습니다.
실문서 원본은 CI에 없으므로 `test:selection`은 원문이 있는 환경에서 별도로 실행해야 합니다.
브라우저 캡처는 Actions artifact에 7일 보관합니다. 이 워크플로 파일만으로 브랜치 보호나
필수 체크 설정이 적용되지는 않습니다.

**Worker 런타임 검증:** `npm run test:runtime`은 실제 Worker 번들을 로컬 workerd와
비영속 R2에서 실행합니다. 모델 응답만 고정하며 외부 네트워크는 차단합니다.
로그인·AI 잠금·결과 미저장·동시 구간 요청·R2 조건부 쓰기를 확인합니다.
운영 R2나 원격 모델을 호출하지 않으며, 종료 시 런타임을 정리합니다.
조회용 `GATE_PASSWORD`와 다른 비밀번호를 사용하고 허용할 사람에게만 전달하세요.

ECR 화면에서 잠금을 해제하면 30분간 AI를 사용할 수 있습니다. 비밀번호는 브라우저 저장소에
보관하지 않고 HttpOnly·Secure·SameSite=Strict 서명 쿠키를 사용합니다. 다시 잠그기·사이트 로그아웃은
제출한 AI 토큰을 서버에서 취소한 뒤 브라우저의 해당 쿠키를 지웁니다. 취소 실패 시 재시도를 안내합니다.
다른 세션의 AI 토큰이나 이미 실행 중인 요청은 취소하지 않습니다. 비밀번호를 변경하면 기존 서명 쿠키도 무효화됩니다.
해제 시도는 IP당 10분에 5회, 전체 200회로 제한합니다. R2 장애 시에도 잠금을 풀지 않습니다.
잠긴 상태에서는 ECR 업로드·추론 API를 직접 호출해도 거부됩니다.
자연어 검색 역시 잠금 해제 전에는 AI를 호출하지 않고 기존 규칙 파서만 사용합니다.
진행 중 다시 잠그면 다음 구간부터 중단합니다. 이미 서버에서 시작한 추론은 취소되지 않습니다.

분석에는 Workers AI 무료 할당량을 사용합니다. [공식 요금표](https://developers.cloudflare.com/workers-ai/platform/pricing/)의
계정당 일일 무료 할당량은 10,000 뉴런이며 UTC 00시(KST 09시)에 초기화됩니다.
`src/ai-budget.js`는 기존 자연어 검색과 ECR 분석을 합쳐 **일일 8,000 뉴런의 보수적 추정 예산**을
예약합니다. 입력 UTF-8 바이트 수, 최대 출력 토큰, 모델 단가와 여유분을 사용하므로 실제 청구량과는 다릅니다.
R2 조건부 쓰기로 동시 요청에서도 예약 누락을 막고, 저장소 장애·예산 소진 시 모델을 호출하지 않습니다.
실패한 호출도 비용이 발생했을 수 있어 예약을 돌려주지 않습니다. 다른 유료 모델로 전환하지 않습니다.
다른 Worker/앱이 같은 계정에서 쓰는 뉴런은 이 카운터에 포함되지 않습니다. **계정 전체의 무과금을
보장하려면 Workers Free 플랜을 유지해야 합니다.** Paid 플랜의 계정 전체 초과 사용은 Cloudflare가 과금합니다.

**결과는 저장하지 않습니다.** 분석 결과는 마지막 요청의 응답으로만 화면에 전달되며 서버·R2 어디에도
남지 않습니다. 저장 결과 조회 API, 결과 목록(`analysis-index.json`), 목록의 ECR 배지, 검색 결과 전체의
ECR 내보내기는 없습니다. 필요하면 분석을 마친 상세창의 **결과 CSV 내보내기**로 내려받으세요.
상세창을 닫거나 다른 공고를 열면 결과가 사라지므로, 다시 보려면 파일을 다시 올려야 하고 비용이 다시 듭니다.

**분석 중 임시 자료.** 분석 중에는 문서를 나눈 구간 텍스트가 `_ecr/jobs/`·`_ecr/parts/`·
`_ecr/refine/`·`_ecr/lease/`에 남습니다. 중단 후 같은 파일로 재개하고 동시 요청을 막는 데 필요한
자료입니다. 문서를 끝까지 분석하면 이 자료를 모두 지웁니다. 그 뒤 같은 작업으로 다시 보낸 요청은
404(다시 올려 주세요)를 받습니다. 끝내지 못한 작업과 예전에 저장하던 결과(`_ecr/notices/`)는 이레 뒤
크론이 걷어 갑니다.
이 경로는 `/data/` 공개 허용 목록에 없고 기존 인증 뒤 `/api/ecr`에서만 접근합니다.
구간 결과는 원문 발췌 근거를 검증하고, 장비 분류·규격 해석·누락은 원문 확인 대상으로 남깁니다.
